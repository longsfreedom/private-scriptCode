## 1. 文档目的

本项目的真实目标不是立刻做到"全自动无人值守"，而是按阶段验证以下问题：

1. 当前环境下是否能稳定截图、识别和输入
2. 是否能在固定配置下稳定完成进图
3. 是否能在地图内稳定发现并交互贪婪祭坛
4. 是否能在异常时安全停止，而不是无限误操作
5. 在上述能力稳定后，是否值得继续做拾取、回城、存仓和补货

---

## 2. 核心结论

项目第一阶段最重要的不是"自动化程度"，而是下面 4 件事：

1. 状态识别是否可信
2. 输入动作是否可控
3. 每一步是否可以校验
4. 失败时是否会立刻止损

合理的发展顺序：

1. 先做平台可行性验证
2. 再做稳定进图
3. 再做地图内祭坛发现与交互
4. 再做安全回城或安全停机
5. 最后才做拾取、存仓、下一轮和补货

**一句话：先证明"稳定进图 + 稳定交互一次祭坛"能成立，再扩成完整刷图闭环。**

## 3. 项目边界

### 3.1 最终目标

最终希望脚本在尽量少人工干预的前提下，完成一轮贪婪刷图流程：

1. 放入地图和圣甲虫
2. 开启地图并进入
3. 在地图内巡逻
4. 发现并交互贪婪祭坛
5. 选择目标选项
6. 处理掉落
7. 回城
8. 存仓
9. 返回初始位置准备下一轮

### 3.2 第一版运行环境约束

第一版只允许在严格固定环境下运行：

1. 固定分辨率
2. 固定窗口模式
3. 固定 UI 缩放
4. 固定语言
5. 固定地图类型
6. 固定圣甲虫组合
7. 固定角色技能方案
8. 固定背包布局
9. 固定仓库页
10. 固定过滤器规则

### 3.3 第一版明确不做

以下内容不纳入第一版承诺范围：

1. 多分辨率兼容
2. 多地图类型兼容
3. 智能全图寻路
4. 自动采购和库存管理
5. 复杂仓库整理
6. 长时间完全无人值守
7. 复杂战斗策略自适应

## 4. 前置可行性验证

在任何业务逻辑开发前，必须先完成可行性验证。只要其中任意一项不成立，后续大模块都应暂停。

### 4.1 验证项

1. 能否稳定截取目标窗口画面
2. 截图是否存在黑屏、延迟、缩放偏移或颜色失真
3. 鼠标移动和点击是否能稳定生效
4. 键盘按键和长按是否能稳定生效
5. 游戏窗口焦点切换后是否会导致输入丢失
6. 固定 UI 元素是否能通过模板匹配稳定识别
7. OCR 在固定字体和固定区域下是否有可接受的识别率

### 4.2 通过标准

1. 连续截图 200 次无明显黑屏和错位
2. 固定按钮点击成功率达到 95% 以上
3. 固定 UI 模板识别成功率达到 95% 以上
4. 关键 OCR 文本在固定区域下识别成功率达到 90% 以上
5. 连续运行 30 分钟不出现明显状态漂移

### 4.3 验证失败时的处理

如果前置验证不通过，不应继续堆业务模块，而应优先解决以下问题：

1. 截图链路
2. 输入链路
3. 分辨率和 ROI 标定
4. 模板采集质量
5. OCR 截图区域和预处理

## 5. 分阶段目标

### M0：平台验证

确认截图、输入、基础识别方案是否可行。

验收：前置可行性验证项全部通过。

### M1：稳定进图

从藏身处到成功进入地图。

验收：连续成功进图 20 次，失败时不会连续乱点。

### M2：祭坛交互

进图后找到祭坛并完成一次有效交互。

验收：多数轮次能成功发现并完成祭坛交互，搜索失败时能安全退出当前轮。

### M3：安全收尾

祭坛交互后的安全回城或安全停机。

验收：失败时能在有限重试后停止，不出现无限循环误操作。

### M4：完整闭环

在前 3 个阶段稳定后，扩展为单轮完整闭环（含拾取、存仓、下一轮启动）。

验收：能连续完成多轮，各环节成功率可量化。

## 6. MVP 定义

### 6.1 MVP 范围

第一版 MVP 定义为以下链路：

1. 人工提前准备地图和圣甲虫
2. 脚本自动进图
3. 脚本自动巡逻
4. 脚本自动识别并交互一次贪婪祭坛
5. 成功后自动回城或安全停机

### 6.2 MVP 成功标准

1. 能连续成功进图 20 次
2. 能在多数轮次中成功完成一次祭坛交互
3. 每一步都有超时和结果校验
4. 失败时最多进行有限重试
5. 失败后能够安全停机，不无限乱点

### 6.3 第一版结束条件

满足以下任一条件即结束当前轮：

1. 祭坛已成功交互
2. 地图搜索超时
3. 卡住恢复失败
4. 状态识别连续失败
5. 用户主动停止

## 7. 关键行为约束

从需求层面对脚本行为提出以下硬性约束：

### 7.1 状态约束

1. 必须采用状态机驱动，不允许散乱 if-else 流程拼接
2. 必须支持 UNKNOWN 状态（无法判断场景时进入）
3. 必须支持 MANUAL_REQUIRED 状态（脚本停止自动操作）
4. 低置信度识别不能直接驱动危险动作
5. 状态不确定时优先停机，不优先硬恢复

### 7.2 交互约束

1. 每次点击后必须有结果校验
2. 不允许连续无校验点击
3. 所有动作必须支持超时和重试次数限制
4. 所有动作必须支持随机微偏移和节流

### 7.3 恢复约束

1. 优先轻量恢复，恢复失败后优先停机
2. 不允许无限循环恢复
3. 不允许在未知状态下继续危险操作

### 7.4 止损约束

以下场景必须直接停止并等待人工处理：

1. 连续多次无法判断状态
2. 连续多次恢复失败
3. 出现未知弹窗或未知界面
4. 截图或输入链路异常
5. 当前画面与任何已知模板严重不匹配

从第一天开始记录以下指标：

1. 截图成功率
2. 固定模板识别成功率
3. OCR 识别成功率
4. 进图成功率
5. 祭坛发现成功率
6. 祭坛交互成功率
7. 平均单轮搜索时间
8. 卡住恢复成功率
9. 安全停机成功率
10. 连续运行轮数

## 9. 风险与前置条件

### 9.1 前置条件

1. 固定显示设置
2. 固定 UI 布局
3. 固定输入映射
4. 固定游戏语言
5. 固定角色技能方案
6. 固定地图和刷图策略
7. 可稳定获取模板和 OCR 样本

### 9.2 主要风险

1. 游戏更新导致模板失效
2. 地图环境变化导致祭坛识别率下降
3. OCR 在特效和滤镜下误读
4. 网络波动导致状态判断失真
5. 长时间运行导致状态漂移
6. 截图或输入链路存在不稳定性
